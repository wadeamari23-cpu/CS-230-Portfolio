# CS 230 Portfolio Reflection


### Briefly summarize The Gaming Room client and their software requirements.

The Gaming Room was a client that wanted to expand their Android game called Draw It or Lose It. They wanted to change it so people could play it on different devices through a web browser. The game has teams trying to guess drawings actively and trying to do so before time runs out. They needed the game to support multiple players and teams, while staying unique, running smoothly, and being secure.

### What did you do particularly well in developing this documentation?

I think I did well when comparing the different operating systems and explaining what each one had to offer. I looked at all the aspects within them to figure out which options would realistically work best for the game. I focused on what the client wanted when decided the best recommendation.

### What about the process of working through a design document did you find helpful when developing the code?

The design document helped me understand why it's important to plan things out before just instantly starting the coding. It made it easier to break down what the program needed and easier for me to figure out how everything would work together. It helped me think about how the application would run on the different systems.

### If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could go back and change something then I would probably improve the security section of my design document. I think I could have used a bit more detail about how to protect player information and avoid giving access to those who aren’t authorized access. If I showcased more specific measures for security then I think it would make the design more complete and help prevent problems in the future.

### How did you interpret the user's needs and implement them into your software design? Why is it so important to consider the user's needs when designing?

For interpreting the user's needs I started by looking at what the client wanted the game to actually do. They wanted to implement multiple players, support for different devices, and a way to keep everything organized and secure. So then I just kept those requirements in mind when deciding what would work best for the design. I think understanding what users need is what's truly important because there's no point in making a program if it genuinely doesn't do what people actually want it to do.

### How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

I looked at the requirements and weighed my options. This let me find which systems and technologies that I personally think would work the best. I compared options and thought about their advantages and disadvantages meant for the game before making my recommendations. I think it’s important to  spend more time testing ideas early and making sure everything works. So that it runs the way it is supposed to before it gets too far into development. I think that would help avoid problems later on.
